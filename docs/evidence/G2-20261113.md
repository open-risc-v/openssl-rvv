# G2 证据包（2026-11-13）

| 项 | 值 |
|---|---|
| 包 | `dev-libs/openssl` |
| 上游固定点 | `3f11738` |
| 上游构建系统 | perl Configure（out-of-source） |
| 被测路径 | AES-128-CBC 回环 + SHA-256 |
| 用例 | `test/cases/01_openssl_aes.sh` |
| 探针 | `test/ossl_harness.c` |

## 做法

`cmake/pkg-build.sh` 用上游**自己的**构建系统把 `${SRC_DIR}` 编到 `<build>/pkg/prefix`；
openssl 走 **out-of-source**（在 `<build>/pkg/bld` 里 `perl ${SRC}/Configure`），源码树不被写入。
`cmake/upstream.cmake` 让探针链接该前缀下的静态库。A 侧 `SRC_DIR=src`，B 侧 `SRC_DIR=baseline`、
`RVV_KERNELS=OFF` —— 两侧唯一变量是源码树（native 下内核宏不产生代码差异）。

## 命令与输出

```bash
cd $(pwd)/openssl-rvv
./test/run_ab.sh
```

```
PASS 00_framework
PASS 01_openssl_aes
== A/B: ALL PASS（2 个用例，A=src vs B=baseline）==
```

探针单跑（A 侧）输出：

```
n=65536 evp=OpenSSL 4.2.0-dev  cipher=compiler: cc -fPIC -arch arm64 -O3 -Wall -DL_ENDIAN -DOPENSSL_PIC -D_REENTRANT -DNDEBUG sha256=b5c66c4dfe737e31145c2cf0a52a7ceadf0045f26dffd6ef3414b0f9d3687365 fnv_ct=cc18494f5e673a69
```

## 结论

G2（baseline 全绿）达成：真实上游库、真实编解码/合成/加解密路径，A/B 产出逐字节一致。
**局限**：native 构建只证明"两侧代码路径一致"，RVV 内核收益要等交叉编译 + 真机才有数字。
